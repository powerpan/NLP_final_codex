這份文件保留首次真人測試前的狀態。其後已完成一次真實文字協作，結果與後續修正見 [LIVE_RESULT_2026-10-19.md](LIVE_RESULT_2026-10-19.md)。

2026-10-19，我們先核對 README、架構、操作和驗證記錄，再閱讀 Provider、排程／狀態、工具、Git／Search、評測和 CLI。原有「離線測試通過不等於模型可用」的判斷成立；真正需要補的是首次接入時的故障處理、預算和可重跑的操作入口。

這輪沒有改變技術棧，也沒有加入 Web UI。當前目錄沒有 `.git`；修改保存在本地，未初始化倉庫、提交、推送或部署。

## 會影響實測的修正

| 原有問題 | 現在的行為 |
|---|---|
| 恢復／並行工作流可能共用啟動時的輸出上限 | 每次請求使用該工作流保存的上限，再與當前 Provider 上限取較小值；上下文檢查包含工具 schema |
| 通知被 A2A 預算拒絕後，operation 留在 RUNNING | 明確保存 FAILED，重播同一次操作取得原錯誤 |
| 取消中的模型請求記為確定失敗 | 記為 UNKNOWN，保留遠端可能已處理／計費的事實 |
| 截斷等回應中的已知 token 用量丟失 | 拒絕部分輸出，同時保存 Provider 回報的用量；評測顯示已知總量與缺報覆蓋率 |
| HTTP 空行 keep-alive 可能不斷延長讀取 | 分段讀取並檢查總期限；仍不宣稱可立即終止 Python 執行緒內的阻塞 socket |
| 部分官方停止原因被誤判為格式錯誤，401／402 等缺少診斷 | 資源不足／中斷按暫時錯誤處理；提供固定且不含憑據的診斷文字 |
| Docker／Git 輸出超限後等程序退出，管道未排空可能卡死 | 終止程序群組並排空剩餘管道；測試涵蓋父程序已退出但子程序仍持有管道 |
| Docker 啟動被取消時尚未登記容器 | 啟動前登記主容器與初始化 helper；清理結果不確定時拒絕重用 |
| probe 第二輪失敗仍返回成功；空 reasoning 也被算作通過 | 只有預期工具結果與明確 OK 才算工具 probe 成功；reasoning 另行如實報告 |
| demo 可能自動回答資料庫中的其他人工等待 | 新執行要求資料庫沒有未完成工作，auto-answer 限本次示範；真實 resume 拒絕未結束 fixture |
| 評測結束後才發現報告不可寫，或覆寫 DB／suite | 模型調用前先以新檔方式預留報告；既有檔案和別名會被拒絕 |

新增 `doctor` 檢查本地配置、Docker daemon 和映像；`run`／`chat`／`evaluate` 可直接設置調用數、任務數和期限。這些限制是每個 workflow 的上限，不是多案例評測或群聊的總上限。

`scripts/live_smoke.zsh` 提供隱藏輸入 key 的入口。它先做最多兩次 probe，再跑最多六次呼叫的純文字案例。文字案例由外部斷言核對 reviewer 的 REPLY 已完成，避免只相信模型的成功聲明；新的資料庫和報告目錄讓每次結果可分開檢查。

## 本機結果與下一步

126 項自動測試在 Python 3.12.4 和 3.14.3 都通過。實際 Docker 測試涵蓋檔案、unittest、持久化、非 root、唯讀根目錄、無外網、cgroup 限制，以及逾時／輸出超限後清理。這是基本隔離和生命周期驗證，沒有進行記憶體／PID 飽和壓力或全面安全審計。完整條件見 [VALIDATION.md](VALIDATION.md)。

尚未使用真實 API key，因此沒有模型完成率、實際 token 費用或人工體驗結論。Search、外部 Git push 和正式 Rubric 也仍待各自驗證。下一步按 [LIVE_TEST.md](LIVE_TEST.md) 輸入 key，先看 probe 和文字協作，再跑檔案案例；不需要先啟用可選 Search 或 Git。
