# 真實協作與新聞任務檢查

本次使用帳戶中的 DeepSeek key，經互動終端的 `TerminalController` 執行真實 SSE、工具及 Docker。API key 沒有寫入報告；SQLite 仍包含任務私密對話與 reasoning，應留在本機。

## 原始失敗與原因

使用者的新聞任務保存在 `data/terminal-live.sqlite`，workflow 為 `wf_e0c69528ecfb4f589d6dc82df0c605f8`，原句是「幫我查美國最近24小時比較火的三條新聞」。檢查以唯讀連線進行，沒有替使用者恢復或修改這個工作流。

任務其實成功搜尋了 3 次、成功抓取了 7 次，另外有 6 次 `WEB_NOT_FOUND` 和 4 次 `WEB_TIMEOUT`。因此 planner 最後「全程沒有網路」的說法不符合工具紀錄。第一個 researcher 收到約 57,709 字元、30,439 字元的兩批搜尋結果，再讀取大型頁面後，snapshot 增至約 182,498 字元，超過 120,000 的上下文上限。父任務只收到失敗代碼，未取得已成功抓取的證據索引；重新委派又重複搜尋和抓取，最後用完 20 次網頁額度。

缺少可信的目前時間，還讓模型花了 4 次網頁請求查時間。另一個 researcher 在 4,096 token 輸出上限被截斷；thinking 也占輸出上限。第一個委派曾因驗收欄位格式錯誤被拒絕，模型後來降低為「非空」驗收。原任務用了 35 次模型請求、325,989 個 API 回報 tokens，期限並未耗盡。這是一組相互影響的執行設計問題，提高總預算無法解決。

另一次受控協作首測保存在 `data/live-tests/collaboration-web-20261019-a/`，香港時間 21:29:02–21:31:06。真實父／子／孫任務、並行模型請求、官方 Search／Fetch 和 Docker 都執行成功，但兩個 coder 最後輸出散文加錯誤 JSON。舊修復提示把格式錯誤混成「缺少產物」，導致重跑測試、重複發布。這輪保留 **FAIL**：8 個任務中 6 完成、2 失敗；46 次模型請求、279,115 tokens。失敗的 coder 已成功發布過檔案，只是沒有通過最終結果驗收，不能說它們完全未產出產物。

協作 b 輪（`data/live-tests/collaboration-web-20261019-b/`）也保留 **FAIL**。7 個子／孫／REPLY 任務全部完成，但 root 在交付時包含只授權給 researcher 的孫任務產物，被 ACL 正確拒絕。缺少 caller 可讀的產物目錄、REPLY 能力說明和具體錯誤 ID，又讓 planner 多做 3 次元資料詢問；最後 JSON 字串未跳脫換行而失敗。32 次模型請求、218,078 tokens、約 99.8 秒。這輪促成授權交接修正，沒有放寬產物 ACL。

## 修正方向

- 格式修復與真正驗收失敗分開：格式修復保留原有授權產物 ID，禁止重跑工具；修復模式在重啟與重試後仍保持。程式驗收失敗則仍可使用工具修改。
- Agent／Bid／格式修復請求採用 DeepSeek [官方 JSON Output](https://api-docs.deepseek.com/guides/json_mode/)；本地仍嚴格驗證欄位和產物授權。另有兩次真實 SSE 請求驗證 JSON 模式、原生工具往返、中文、換行與引號，通過並回報 1,053 tokens（`data/live-tests/json-mode-20261019/report.json`）。
- 網頁原始結果保存在操作帳本，送模型的內容受控，完整已保存內容可分段讀取；同工作流成功的相同請求可以重用。
- 每次模型請求提供可信時間、實際角色工具、剩餘共享預算和已取得的公開網頁證據。失敗子任務不再讓父任務看不見先前成功的檢索。
- 委派工具完整描述驗收格式。終端分開呈現「流程結束」與執行證據，顯示失敗子任務和工具錯誤，不以文字非空宣稱目標達成。
- 產物交接依接收方實際授權提供 ID／檔名，非傳遞授權的產物在父任務觀察中標示未交付；原始紀錄及 grants 不變。WORK／REPLY 分別列出工具，驗收錯誤點名不合法 ID 和已授權替代，避免以詢問子 Agent 猜測本地目錄。
- 新工作流預設輸出上限調為 8,192 tokens；已保存工作流的上限不會被新設定覆蓋。工具逾時採用保存的工作流設定。

## 新聞原句重測

香港時間 21:46:15 啟動，約 218.5 秒結束。`data/live-tests/news-20261019-b/` 的兩個任務全部完成，19 次模型請求、405,278 tokens。8 次 Search 成功；10 次 Fetch 中 5 次成功、5 次失敗，模型取得可用來源後繼續完成；planner 另有 5 次本地證據讀取，沒有為核對內容重抓。

獨立讀取全文後，確認交付的是三個不同事件：對俄制裁、美國總統背書納坦雅胡、華府球場改建；五個最終引用都能對應已成功抓取的文章。三則主要來源正文刊載時間落在要求窗口內，時區換算採媒體所在地的 MYT／北京時間／KST，擷取正文未明寫時區。這是報導刊載時間，不是每個事件精確發生時刻；兩則外交、一則國內政治，結果已明示不是實測熱門榜前三名。

原 `report.json` 的自動結果是 FAIL，原因是測試程式的 URL 正規式吞入中文全形標點及相鄰文字。修正審核器並補回歸後，重新唯讀核對原資料得到 **PASS**，寫入獨立的 `audit-corrected.json`，原報告與資料庫保持不變，沒有為此重跑付費請求。可直接讀 [新聞結果](../data/live-tests/news-20261019-b/news-result.md)。

## 協作 c 輪：修復後通過

香港時間 21:55:11–21:56:14，`data/live-tests/collaboration-web-20261019-c/report.json` 為 **PASS**。兩輪共 25 次模型請求、172,873 tokens，7 個任務全部完成，沒有重試或修復；本次使用的原始碼 SHA-256 與結束時一致。

- 第一輪的 planner → researcher → reviewer 形成三層 WORK；coder 同層並行，另有 reviewer REPLY。實際模型請求時間重疊，並非只有佇列中同時存在任務。
- 官方 Search 1 次、Fetch 2 次全部成功，來源為官方 Search／Fetch 文件；本地保存內容讀取 2 次。沒有把預覽的省略當成抓取失敗。
- coder 在真實 Docker 跑 4 項 unittest，驗收命令通過；其最終發布的 `counter.py` 另在獨立 Docker 工作區通過固定 8 項外部案例。
- 第二輪提出問題後，測試驅動器關閉並重開 SQLite／controller，再提交固定回答。3 個產物以新 ID 複製到新 workflow，內容和 SHA 不變；reviewer 匯入並讀取，沒有新增網頁請求。這是程式答覆的恢復測試，不是實際真人審批。
- 6 個等待各只解決一次，11 個 attempts 均結束；工具配對、產物授權／雜湊、DB integrity／外鍵均通過，沒有孤兒或未完成操作。容器已清理，任務卷依既有持久化設計保留。

仍觀察到一個文字遵從偏差：續輪要求最多 3 句，模型給了 4 句。工程 PASS 指上述執行契約，不能宣稱每一項自然語言格式要求都完全遵守，也沒有以此單例建立一般模型品質結論。

## 重現入口

`scripts/live_collaboration_check.py` 是明確選用的付費測試入口，先讀 `DEEPSEEK_API_KEY`，否則讀 macOS Keychain 中 `Multi-Agent-Platform.DeepSeek` 的目前帳戶項目。它不列印 key，拒絕覆寫既有輸出目錄，並保存實際程式檔 SHA-256、輸入、政策與 API 回報用量。

```zsh
.venv/bin/python scripts/live_collaboration_check.py \
  --run-dir data/live-tests/新協作測試目錄

.venv/bin/python scripts/live_collaboration_check.py --scenario news \
  --run-dir data/live-tests/新新聞測試目錄
```

協作測試是指定工具與任務結構的整合案例，包含跨輪產物及提問後重開資料庫；提問由測試驅動器回答，不是真人驗收。新聞案例只送出使用者原句，使用與新 CLI 相同的 high effort、8,192 output tokens、120,000 context chars、20 次 web、20 秒工具逾時和 600 秒期限。它沒有逐步工具提示。

自動檢查會核對任務終態、實際並行、串流、來源、產物 SHA／授權和 SQLite 完整性。程式另用固定 8 項外部案例在獨立 Docker 工作區檢查。新聞的自動通過只代表檢索和引用契約符合，發表時間、事實和新聞相關性需要另讀來源核對，不能以三個網址代替內容審核。
